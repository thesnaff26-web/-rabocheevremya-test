# Геометрия Могоча — Уруша: результат исследования

Дата проверки: 31 октября 2026.

После исследования подготовлено экспериментальное подключение отдельного файла `rail/route-geometry.geojson` к приблизительной архивной привязке. Условия и резервная копия описаны в [документе подключения](geometry-integration-and-rollback.md). Исходный исследовательский снимок ниже остаётся неизменным.

## Что подготовлено

`rail/research/mogocha-urusha-osm.geojson` — отдельная выгрузка геометрии железнодорожных путей OpenStreetMap в регионе Могоча — Уруша. Это исследовательский набор; он не подключён к расчёту текущего км/ПК и не включён в обязательный офлайн-кэш приложения.

Выгрузка содержит 718 линий и 11 000 уникальных вершин:

| Тип пути по тегам OSM | Линий |
| --- | ---: |
| Главные пути (`usage=main`, без `service`) | 313 |
| Станционные пути (`service=siding`) | 127 |
| Парковые пути (`service=yard`) | 65 |
| Подъездные пути (`service=spur`) | 165 |
| Съезды (`service=crossover`) | 48 |

Для главных путей медианное расстояние между вершинами составляет 60,0 м; 95-й процентиль — 285,2 м; максимум — 1341,2 м. Длинный прямой сегмент сам по себе не означает отсутствие покрытия, но требует проверки геометрии. Объекты, пересекающие рамку запроса, выгружаются целиком: рамка не равна точной эксплуатационной границе участка.

В старом `corridor.json` в километровом диапазоне 6895–7215 находятся 379 координатных точек с максимальным шагом 1000 м. Эти числа относятся к разным представлениям и не являются прямым сравнением точности.

## Что не найдено и не подтверждено

В выгрузке нет узлов `railway=milestone`. Дополнительный запрос объектов с `railway:position` и `railway:milestone` в той же рамке также вернул 0 объектов. Ни одна из 313 линий главных путей не имеет `railway:track_ref`.

Следовательно, из этого набора нельзя автоматически получить проверенную железнодорожную отметку км/ПК или гарантированно определить чётный/нечётный путь. Накопленная геометрическая длина линии не должна выдаваться за официальный километраж. Параллельные и станционные пути необходимо обрабатывать отдельно; направление отрисовки OSM и `oneway` не заменяют проверку чётности.

Исходный источник старой базы по-прежнему маркирует свою геометрию как `draft_from_legacy_ek`, а импорт — как `non_authoritative_import_seed`. Более свежая дата загрузки не делает эту привязку проверенной.

## Как проверять подключение

1. Построить связный граф главных и станционных путей. Проверить разрывы и альтернативные ветви, не соединять их произвольными прямыми.
2. Отдельно хранить геометрию и таблицу железнодорожных километровых опорных точек с источником и точностью. Не создавать опорные точки из неподтверждённых показаний самого приложения.
3. Сопоставлять последовательность GPS-измерений с графом, учитывая движение, расстояние и неоднозначные варианты. Хорошее совпадение с рельсовой линией ещё не подтверждает км/ПК.
4. Проверять километровую привязку на независимых известных отметках, включая станции и кривые. Для заявлений о точности нужны измеренная ошибка и достаточное покрытие контрольными точками.
5. Считать расчёт км/ПК проверенным лишь после этой проверки. При недостатке опорных данных оставлять явный режим приблизительного обзора.

## Воспроизводимость и источник

Из корня проекта:

```sh
python3 scripts/build-rail-geometry.py --download
```

Либо повторить преобразование ранее скачанного ответа:

```sh
python3 scripts/build-rail-geometry.py --input /path/to/overpass-response.json
```

Скрипт отклоняет ответ с сообщением о неполной выдаче Overpass, сохраняет исходные координаты, не вычисляет км/ПК, записывает SHA-256 входного файла и время снимка OSM в метаданные результата. Запись результата выполняется через временный файл.

Источники:

- [OpenStreetMap API](https://api.openstreetmap.org/api/0.6/map?bbox=121.9,53.9,122.0,54.0) — подробная независимая выгрузка района станции Ерофей Павлович для проверки наличия станционных путей.
- [Overpass API](https://overpass-api.de/api/interpreter) — рамка `53.6,119.6,54.3,123.1`; полный запрос записан в `metadata.source_url` GeoJSON и в скрипте.
- [Авторство и лицензия OpenStreetMap](https://www.openstreetmap.org/copyright).
- [Источник старой геометрии](https://bloknot-mashinista-bot.ru/assets/tracker/sections/ek069-vikhorevka-gyrshelun-sayanskaya-s29.json) — использован для проверки происхождения существующей базы.
